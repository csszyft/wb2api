# wb2api v1.9.45

新增代理池和每账号固定出口。可批量粘贴代理链接，后台检测实际公网 IP，再按每个 IP 的账号容量分配；已有绑定保存到数据目录，重启后保持不变。

## 功能

- 支持 HTTP、HTTPS、SOCKS5 和 SOCKS5h。完整 URL、常见四段字段顺序、`用户名:密码@主机:端口`、竖线／逗号分隔及 JSON 均可导入。未写协议的行使用面板选定的类型，非法条目单独提示，正确条目正常保存。
- 国家／分组完全保留用户输入，`sg` 只是一种示例。从基础链接生成代理账号时，默认在用户名后添加 `.代理账号`，也支持 `{account}` 模板。完整代理用户名决定代理商提供的粘性出口，程序不会改写用户导入的用户名或密码。
- 每个实际 IP 可设置绑定多少个 WorkBuddy 账号，默认 `1`；多个链接检测到相同 IP 时共用容量。可自动填补未绑定账号、按国内／国际区域一键分配、手动固定出口，或明确执行重新分配。容量不足时保留未分配状态，不静默改用其他出口。
- 新“出口代理”页显示检测进度、公网 IP、容量、绑定账号、检测失败和出口冷却；账号池显示各账号的出口。检测最多三个链接同时进行，每次检测有超时，导入回执不等待网络完成。
- 聊天、凭证刷新、余额、模型目录、资料和任务请求统一走账号绑定代理。每条代理链接使用独立连接池；SOCKS5h 由代理端解析目标域名，HTTP/1 临时回退也保留代理绑定。
- 代理认证、连接失败与账号故障分别处理，不累计健康账号的故障或禁用计数。WAF 多账号拦截按实际 IP 隔离，其他出口继续轮转。代理不可用不作为额度耗尽，保留国际免费 4.1 → SG → 国内同名 4.1 的回退条件及积分保留、每日 Token 限额。

代理池默认不启用。启用后默认未绑定账号等待分配；如需原出口，可打开“未绑定账号使用原出口”或在账号绑定中明确选择。固定代理发生故障时，不自动改为直连。

代理认证地址与绑定保存在状态文件同目录的 `proxy-pool.json`，如 `data/proxy-pool.json`。迁移和升级保留数据目录即可；面板列表不返回代理密码。实际粘性 IP 由代理商提供，检测记录用于容量分组，代理商变更出口后可再次检测。

## 验证与升级

全量 `go test ./...`、`go vet ./...` 和 egress、pool、upstream、server、panel 的 `-race` 检查通过。测试使用真实本地 HTTP 代理、HTTPS CONNECT 隧道和带认证的 SOCKS5 服务，覆盖远程 DNS、固定绑定、跨重启恢复、并发容量、异步检测、出口隔离和付费回退边界。浏览器已验证导入、检测进度、实际 IP 和账号分配。

镜像：`ghcr.io/csszyft/wb2api:v1.9.45`，同时更新 `latest`，支持 Linux amd64 / arm64。Release 提供 Windows amd64、Linux amd64 / arm64、macOS amd64 / arm64 五个平台包及 `SHA256SUMS`。

```bash
docker compose pull
docker compose up -d
```

二进制部署替换程序后重启，在“出口代理”页导入代理并启用。保留现有配置、凭证和用量数据。
